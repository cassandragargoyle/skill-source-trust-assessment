# Changelog

All notable changes to the skill and its methodology. The methodology version is stated in `SKILL.md` (`metadata.methodology-version`), in the header of `references/methodology.md` and in the schema `$id`.

## [Unreleased]

## [0.1.2] - 2026-11-11

Methodology 0.1.1 (unchanged).

### Added

- Claude Code plugin and marketplace manifests (`.claude-plugin/`), so the skill installs with `/plugin install`.
- Release workflow: a pushed `vX.Y.Z` tag builds `source-trust-assessment-X.Y.Z.zip` (for Claude.ai and Claude Desktop) and creates a GitHub release from the matching CHANGELOG section.
- README: install instructions for every channel, limitations (not legal advice, AI assessments are unverified) and profile status (`bim` is a draft).
- Test that `SKILL.cs.md` and `plugin.json` carry the same version as `SKILL.md`.
- README: data and privacy section (what the skill runs, fetches and stores) for the plugin directory review.
- Plugin icon `.claude-plugin/icon.png`: the network of the CassandraGargoyle mark around a green shield with a check mark, generated by `docs/icon/icon.py`.

## [0.1.1] - 2026-11-11

Methodology 0.1.1.

### Changed

- Evidence `relation` codes (`confirms`, `partially-confirms`, `contradicts`, `context`) are now defined in the methodology (§ 4) and the vocabulary; `SKILL.md` step 4 uses them instead of the inconsistent wording "only partly supports". Evidence criteria were added to the vocabulary. Tests check both code lists against the schema, methodology and vocabulary.
- `SKILL.cs.md`: informative Czech translation of `SKILL.md`; the English version prevails in case of conflict.
- `SKILL.md` description lists example trigger phrases in Czech; a new rule asks for the summary and free-text fields in the user's language (codes and quotes unchanged).

## [0.1.0] - 2026-11-10

### Added

- `source-trust-assessment` skill: workflow and rules in `SKILL.md`.
- Methodology 0.1.0: Admiralty Code (A–F, 1–6), legal authority and status, assessment levels (publisher, document, claim), evidence criteria, provenance, profile rules.
- Region profiles `cz` (Czech) and `eu`; domain profile `bim` (draft).
- `assessment.schema.json`, template and SKOS vocabulary.
- `validate_assessment.py` validator (standard library only) with tests.
- ADR-001 (Admiralty Code instead of a weighted score), ADR-002 (core and profiles, repository layout).
